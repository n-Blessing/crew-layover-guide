# Crew Layover Guide

A small Astro site for cabin crew layover notes. Cities and tips are Sanity documents. The pages list layover cities, then show one city's tips grouped by category, with a category filter.

The sample copy is **example data**. It is not verified travel, safety, or medical advice. Airport codes, currencies, and timezones in the sample are standard reference facts. Everything marked Example is placeholder text for the demo.

Studio, the CLI, and the Astro client default to Sanity project `p4yybrla`, dataset `production`. Environment variables override those defaults. Until that dataset has published cities, the pages render `seed/seed.ndjson`.

## What you have to do yourself

Code in this repo cannot create your Sanity account or deploy under your name.

1. Log in to the existing project `p4yybrla` at [sanity.io/manage](https://www.sanity.io/manage).
2. Import `seed/seed.ndjson` into the `production` dataset and publish the documents.
3. Add the CORS origins listed below.
4. Deploy the site (Netlify or Vercel) and, if you want Studio on Sanity's host, run `npx sanity deploy`.
5. Rewrite the example tips with notes you have actually checked. Turn off **Example data** on those tips.
6. Write any Guest Author article yourself. This README is setup documentation, not that article.

## Run the site

```bash
npm install
npm run dev
```

Open http://localhost:4477. With an empty `production` dataset, the pages still read `seed/seed.ndjson` and a banner says so. After you import and publish cities, the same commands read from project `p4yybrla`.

`npm run build` also works with no `.env` file. The static site is written to `dist/`.

## Sanity project

The repo is already pointed at project `p4yybrla`, dataset `production` (`sanity.shared.mjs`). Do **not** run `npm create sanity@latest` inside this folder. That command scaffolds a new Studio and can overwrite files.

`production` is public, so the site can read published documents without a token. Log in when you want to edit:

```bash
npx sanity login
```

## Environment variables

You do not need a `.env` file for this project. To point the app at a different project, copy the example and change the ids:

```bash
cp .env.example .env
```

`.env.example` already contains:

```bash
PUBLIC_SANITY_PROJECT_ID="p4yybrla"
PUBLIC_SANITY_DATASET="production"
SANITY_STUDIO_PROJECT_ID="p4yybrla"
SANITY_STUDIO_DATASET="production"
```

Any of those values overrides the defaults in `sanity.shared.mjs`. `PUBLIC_` values are visible in the browser. `SANITY_STUDIO_` values are what the Studio CLI and the embedded Studio read. Sanity inlines every `SANITY_STUDIO_` value into the Studio bundle, so do not put a token in one. See [Sanity's environment variable docs](https://www.sanity.io/docs/studio/environment-variables).

For a **private** dataset, create a viewer token at [sanity.io/manage](https://www.sanity.io/manage) and set:

```bash
SANITY_API_READ_TOKEN="your-read-token"
```

Leave it unset for a public dataset. Never commit `.env`.

## Import the example content

From this folder, with `.env` filled in and the CLI logged in:

```bash
npx sanity datasets import seed/seed.ndjson production --replace
```

That command is the current Sanity CLI form (`sanity datasets import`). `--replace` overwrites documents that use the same `_id`. Use `--missing` instead if you have already edited those documents and do not want the seed to overwrite them.

The readable source for the seed is `scripts/generate-example-seed.mjs`. After editing it, regenerate the file you import:

```bash
npm run seed:write
```

The seed has four cities: Brussels (BRU), Dubai (DXB), Lagos (LOS), and Nairobi (NBO). Every tip has `isExample: true` and a title that starts with `EXAMPLE:`.

Hero images are optional. The seed does not include any. Add one on the city document in Studio when you have a photo you can use, and fill in the alternative text. The site shows a coloured panel when there is no image.

## Studio and the site locally

Two processes:

```bash
npm run dev
```

Site and embedded Studio: http://localhost:4477 and http://localhost:4477/admin

The embedded Studio uses hash routing (`/admin#/...`), which is what `@sanity/astro` uses for a static build. Refresh stays on `/admin`. See [Embedding Sanity Studio in Astro](https://www.sanity.io/docs/astro/embedding-studio-in-astro).

```bash
npm run dev:studio
```

Standalone Studio on http://localhost:3333. Use this if you prefer the Studio's own dev server. `npm run dev:studio` runs `sanity dev --port 3333`.

### CORS

Studio runs in the browser and calls the Sanity API, so project `p4yybrla` has to allow the origin.

In [sanity.io/manage](https://www.sanity.io/manage), open project `p4yybrla`, then **API** → **CORS origins**, and add:

- `http://localhost:4477` (embedded Studio on the Astro dev server)
- `http://localhost:3333` (standalone `sanity dev`)
- `https://crew-layover-guide.sanity.studio` (hosted Studio, after `npx sanity deploy` claims the hostname from `studioHost` in `sanity.cli.ts`)
- the production website origin, once the Astro site has one

Enable **Allow credentials** on each of those origins. Only do that for domains you control. Allowing credentials on a third-party domain can expose the project. Sanity's note on that is in the embedding doc linked above.

### Edit the content model

| Type | Fields |
| --- | --- |
| `city` | name, slug, country, airport code, currency, timezone, hero image, summary |
| `tip` | title, category (`food`, `transport`, `rest`, `sightseeing`, `safety`), Portable Text body, time needed, cost level (`free`, `low`, `moderate`, `high`), city reference, example flag |

Required fields are validated in `src/sanity/schemaTypes/`. The Studio desk lists cities, all tips, and tips by category. The Vision plugin is there for GROQ.

After a schema or query change:

```bash
npm run typegen
```

That runs `sanity schema extract --enforce-required-fields --force` and `sanity typegen generate`. Commit `schema.json` and `src/sanity/sanity.types.ts`. Queries have to stay in `defineQuery` variables with unique names. See [Sanity TypeGen](https://www.sanity.io/docs/apis-and-sdks/sanity-typegen).

Check the schema, types, seed, and lint together:

```bash
npm run check
```

## Deploy

The site is a static Astro build. Content is fetched at build time. Publish again after you change content in Studio, or add a webhook later. This repo does not include a webhook.

### Astro site on Netlify or Vercel

- Build command: `npm run build`
- Output directory: `dist`
- Node.js: 22.x, matching `engines`
- Environment variables: the same `PUBLIC_SANITY_*` and `SANITY_STUDIO_*` values as `.env`. Add `SANITY_API_READ_TOKEN` only for a private dataset.

Netlify and Vercel both detect Astro. Set the variables in the host's UI, then deploy. Do not put the token in the repository.

When you know the public URL, you can set `site` in `astro.config.mjs`. It is unset on purpose so the repo does not invent a domain.

### Studio on Sanity hosting

From this folder, logged in:

```bash
npx sanity deploy
```

The CLI builds Studio and deploys it to Sanity hosting. `sanity.cli.ts` sets `studioHost` to `crew-layover-guide`, so the suggested URL is `https://crew-layover-guide.sanity.studio` if that hostname is free. You can also pass `--url crew-layover-guide` (see `npx sanity deploy --help`). Add that origin to the CORS list above after the hostname is claimed. The embedded `/admin` route still works on the static host because it uses hash routing.

Optional, for MCP tools that validate documents against a deployed schema:

```bash
npx sanity schemas deploy
```

## Sanity agent skills and MCP in Cursor

Sanity publishes an MCP server and agent skills. The commands below are from [Get started with AI-powered Sanity development](https://www.sanity.io/docs/ai/get-started), [the MCP server doc](https://www.sanity.io/docs/ai/mcp-server), and [Agent skills](https://www.sanity.io/docs/ai/skills). This repo does not invent extra package names.

**MCP.** `.cursor/mcp.json` already contains the official server:

```json
{
  "mcpServers": {
    "Sanity": {
      "type": "http",
      "url": "https://mcp.sanity.io"
    }
  }
}
```

Open the project in Cursor. Cursor should prompt you to authenticate with OAuth. You can also run:

```bash
npx sanity@latest mcp configure
```

That detects Cursor and writes the MCP config. If OAuth gets stuck, the Sanity doc says to run **Cursor: Clear All MCP Tokens** from the command palette, then connect again. Do not commit an `Authorization` bearer token in `mcp.json`.

**Skills.** From this folder, with Node.js 22.20 or later:

```bash
npx skills add sanity-io/agent-toolkit
```

Or, in Cursor chat, install the marketplace plugin:

```text
/add-plugin sanity
```

The plugin bundles the MCP server, skills, and commands. Skills are the best-practice guides (GROQ, schema, Portable Text, TypeGen, and others). MCP is the live connection to your project. Sanity's own docs say to use both.

A project rule in `.cursor/rules/sanity-layover.mdc` points agents at the schemas, the queries, and those official install steps. `.cursor/rules/content-releases.mdc` tells an agent to leave new cities and tips in a Content Release.

Sanity's full docs index for agents: https://www.sanity.io/docs/llms.txt

### Ask an agent to add a city, then review it

The public site reads with the `published` perspective (`astro.config.mjs` and `src/lib/content.ts`). GROQ also skips `drafts.**` and `versions.**`. A Content Release stays off the site until someone publishes it in Studio and you rebuild.

Sanity's MCP server can create a release and write documents into it. From the [MCP server docs](https://www.sanity.io/docs/ai/mcp-server): `create_release` does not schedule or publish, and publishing a release is not available from the MCP tools. `create_documents` writes a release version when you pass a `releaseId`. `publish_documents` is a separate tool. This repo's rule says not to call it.

Paste this to a Cursor agent after the Sanity MCP server is connected and you have authenticated:

```text
Using the Sanity MCP server, add a layover city and two tips as a Content Release, not as published documents.

1. Call create_release with a title like "Add Accra layover". Do not schedule it.
2. Call create_documents with that releaseId for one city and two tips. Use the city and tip fields in src/sanity/schemaTypes. Set isExample to true and start tip titles with "EXAMPLE:" unless I have given you notes I have checked.
3. Do not call publish_documents. Do not publish, schedule, or delete the release.
4. Reply with the release id and the document ids.
```

Then, in Studio, open that release, read the documents, and publish the release yourself. Run `npm run build` again (or your host's rebuild) so the static pages pick up the published documents. Until that publish, Crew Help and the city pages will not show the new notes.

### Crew Help

`/help` answers from published tips only. It quotes the tip it used and links to it. If the question does not overlap a published tip, it says "I don't know, ask your purser."

The page does not call a language model, so it does not need a model key. Sanity Context is included on the Free plan (one Knowledge Base), but its quick start is a separate index and still needs your own model. This demo stays on GROQ and the published tips instead.

## Layout

```text
astro.config.mjs          @sanity/astro client and embedded Studio at /admin
sanity.config.ts          Studio schema, desk, Vision
sanity.cli.ts             CLI project id, studioHost, and TypeGen paths
sanity.shared.mjs         Default project id p4yybrla, dataset production, studio host
src/lib/queries.ts        GROQ queries (defineQuery), published perspective filters
src/lib/content.ts        Sanity fetch, or the local seed when no project id is set
src/lib/crew-help.ts      Match a question to one published tip
src/sanity/schemaTypes/   city and tip
seed/seed.ndjson
scripts/generate-example-seed.mjs
.cursor/mcp.json          Official Sanity MCP server, no token
```

Pages:

- `/` lists cities
- `/cities/[slug]` shows one city, tips grouped by category, and a category filter
- `/help` answers from published tips, or tells you to ask your purser
- `/admin` is the embedded Studio
